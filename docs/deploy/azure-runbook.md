# Aurafit on Azure — deploy + pause/resume runbook

This is the operator's manual for the Azure deployment scaffolded by
[azure.yaml](azure.yaml), [Dockerfile](Dockerfile), and [infra/](infra/).
Everything ships into a single resource group in **East US 2** so you can
pause / resume the whole thing with one command.

## What gets created

| Resource | Purpose | Idle cost (after `azure:stop`) |
| --- | --- | --- |
| Azure Container Registry (Basic) | Holds web + crawler images | ~₹400/mo (always-on, can't pause) |
| Log Analytics workspace | ACA logs | ~₹0–50/mo |
| Container Apps environment | Shared runtime | ₹0 |
| Container App `aurafit-web` | Next.js, public HTTPS | **₹0** (min=0, max=0 when paused) |
| Container App `aurafit-crawler` | Playwright + FastAPI, internal-only | **₹0** when paused |
| Postgres Flexible Server (B1ms, 32 GB, pgvector) | Application DB | **~₹250/mo** storage when stopped |

**Idle bill (`npm run azure:stop`)**: ~**₹650/mo** (ACR + Postgres storage + logs).

**Active bill while testing (`npm run azure:start`)**: ~**₹400–500/day** if left running 24/7
(Postgres ~₹210/day + warm Container Apps ~₹170/day). **Always run `azure:stop` when done.**

**Default after `azd deploy`**: apps scale to **zero** when idle (minReplicas=0). Postgres
keeps running until you stop it — run `npm run azure:stop` after deploys.

## One-time prerequisites

1. **Install tools** (one time):

   ```bash
   brew install azure-cli azd
   ```

2. **Log in** to Azure with an account that has permission to create resources
   in your target subscription:

   ```bash
   az login
   azd auth login
   ```

3. **Push your env values into azd**. This reads `.env.local` and pushes
   every key Bicep needs (Clerk, Azure OpenAI, Azure Storage) into the azd
   environment. One command:

   ```bash
   npm run azure:setup
   ```

   That's the whole step. It creates an azd env named `aurafit-prod` (or
   reuses one if you already have it), sets:

   - `AZURE_LOCATION=eastus2` — Container Apps + ACR + Log Analytics
   - `POSTGRES_LOCATION=centralindia` — Postgres (separate because this
     subscription could create Standard_B1ms/Postgres 16 there during the real
     provisioning probe).

   It also generates a fresh `CRAWLER_API_KEY` and validates that nothing is
   missing. If you later want to change the Postgres region, rerun
   `scripts/probe-postgres-real.sh` first, then override with the proven region:

   ```bash
   azd env set POSTGRES_LOCATION centralindia
   ```

   The Postgres admin password is auto-generated by azd via the
   `secretOrRandomPassword` substitution in `infra/main.parameters.json`.

## First deploy

From the repo root:

```bash
npm run azure:up        # equivalent to: azd up
```

This does everything: creates the RG, ACR, Log Analytics, ACA env, Postgres,
Container Apps; then builds both images via ACR Tasks (no local Docker needed)
and deploys them. First run is **8-12 minutes**.

When it finishes, azd prints the web URL (e.g.
`https://aurafit-web.<random>.eastus2.azurecontainerapps.io`).

### One-time DB bootstrap

The Postgres server is up but the schema isn't applied yet. Run:

```bash
npm run azure:db-init
```

This:

1. Adds your machine's IP to the Postgres firewall (temporary).
2. Runs `CREATE EXTENSION IF NOT EXISTS vector / uuid-ossp / pgcrypto`.
3. Runs `prisma migrate deploy` to create all tables and indexes.
4. Removes the temporary firewall rule.

Smoke-test the API:

```bash
curl https://aurafit-web.<random>.eastus2.azurecontainerapps.io/api/health
# → {"ok":true,"service":"aurafit-web","time":"..."}
```

## Day-to-day: pause / resume

```bash
npm run azure:start      # before testing — starts Postgres, warms web + crawler (~90s)
npm run azure:stop       # when finished — near-zero compute (~₹650/mo idle floor)
npm run azure:status     # paused vs active + rough burn
```

**Workflow**

1. Before opening the mobile app or running generations: `npm run azure:start`
2. Test / demo / develop
3. When finished: `npm run azure:stop` (non-negotiable for cost control)

Optional — Postgres on, apps scale on demand (cheaper than warm, slower first request):

```bash
npm run azure:start -- --scale-to-zero
```

`stop` does:

- `az postgres flexible-server stop` (storage-only billing)
- `az containerapp update --min-replicas 0` for both apps (scale to zero;
  Azure requires max ≥ 1, so replicas spin up only on traffic)

`start` does the inverse.

## Code changes after first deploy

When you edit code in `src/` (Next.js) or `services/product-crawler/` and
want to ship a new version:

```bash
npm run azure:deploy           # deploys both services
npm run azure:deploy -- --service web      # web only
npm run azure:deploy -- --service crawler  # crawler only
```

Each deploy builds via ACR Tasks, pushes a new image, and rolls the Container
App with zero downtime.

If you change `prisma/schema.prisma`:

```bash
npm run db:migrate              # creates a new migration locally
npm run azure:deploy -- --service web
npm run azure:db-init           # applies the new migration to prod DB
```

## Mobile app: point at Azure

After the first successful deploy, get the web URL:

```bash
azd env get-values | grep AZURE_WEB_APP_URL
# AZURE_WEB_APP_URL="https://aurafit-web.<random>.eastus2.azurecontainerapps.io"
```

Then update the EAS preview environment so the mobile app talks to Azure
instead of localhost:

```bash
cd apps/mobile
eas env:update preview \
  --variable-name EXPO_PUBLIC_API_URL \
  --variable-value "https://aurafit-web.<random>.eastus2.azurecontainerapps.io" \
  --type plain
```

Bump the mobile version so the install isn't ignored:

```bash
# Edit apps/mobile/app.json:
#   "version": "1.0.2",
#   ...
#   "android": { "versionCode": 3, ... }
```

Build a new APK:

```bash
cd apps/mobile
npx eas-cli build --platform android --profile preview
```

Install the resulting APK and the "Network request failed" disappears.

## Tearing down completely

If you want zero ongoing cost (loses the database):

```bash
azd down --purge
```

This deletes the resource group and all resources in it. Recreate any time
with `npm run azure:up` followed by `npm run azure:db-init`.

## What NOT to deploy here

- Local Postgres (`docker compose -f docker-compose.postgres.yml`) — that's
  for `npm run dev` only.
- The mobile app — it's built with EAS, lives in `apps/mobile/`.
- Existing Azure OpenAI resources — referenced, not redeployed.
- Existing storage account `aurafit` — referenced, not redeployed.
